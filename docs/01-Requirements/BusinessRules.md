## 1. 角色权限规则

### 1.1 角色定义

| 角色代码 | 角色名称 | 描述 | 数据范围 |
|----------|----------|------|----------|
| `ADMIN` | 体育部管理员 | 系统最高权限，管理所有数据 | 全部数据 |
| `TEACHER` | 教师/裁判/教练 | 成绩录入、赛程查看、报名审核 | 全部数据（只读为主） |
| `STUDENT` | 学生 | 浏览赛事、报名参赛、查看成绩 | 仅自己的报名/成绩数据 |

### 1.2 权限规则

#### BR-AUTH-001：登录认证规则
```
规则：用户必须通过用户名+密码登录，系统返回JWT Token
Token有效期：24小时
Token刷新：前端在Token过期前30分钟自动刷新
失败处理：连续5次登录失败，账号锁定30分钟
```

#### BR-AUTH-002：接口权限规则
```
规则：所有业务接口必须携带有效Token
无Token：返回401 Unauthorized
Token过期：返回401，前端跳转登录页
权限不足：返回403 Forbidden
```

#### BR-AUTH-003：数据权限规则
```
ADMIN：可查看/操作所有数据
TEACHER：可查看所有数据，仅可操作成绩录入
STUDENT：仅可查看/操作自己的报名记录和成绩
```

## 2. 赛事管理规则

### 2.1 赛事状态机

```
                    ┌─────────────┐
                    │   草稿      │
                    │  (DRAFT)    │
                    └──────┬──────┘
                           │ 发布
                           ▼
                    ┌─────────────┐
         ┌──────────│   报名中    │──────────┐
         │          │(REGISTERING)│          │
         │          └──────┬──────┘          │
         │                 │ 开始比赛         │
         │                 ▼                 │
         │          ┌─────────────┐          │
         │          │   进行中    │          │
         │          │ (ONGOING)   │          │
         │          └──────┬──────┘          │
         │                 │ 结束比赛         │
         │                 ▼                 │
         │          ┌─────────────┐          │
         └─────────▶│   已结束    │◀─────────┘
           取消      │ (FINISHED)  │   取消
                    └─────────────┘
```

### 2.2 赛事业务规则

#### BR-EVENT-001：赛事创建规则
```
前置条件：用户角色为 ADMIN
必填字段：赛事名称、赛事类型、开始日期、结束日期、负责人
默认状态：草稿(DRAFT)
约束：
  - 赛事名称不能重复（同一年度内）
  - 结束日期必须大于等于开始日期
  - 赛事类型必须为字典表中的有效值
```

#### BR-EVENT-002：赛事修改规则
```
允许修改的状态：草稿(DRAFT)、报名中(REGISTERING)
禁止修改的状态：进行中(ONGOING)、已结束(FINISHED)
约束：
  - 报名中状态下，不能修改开始日期
  - 已有报名记录时，不能修改赛事类型
```

#### BR-EVENT-003：赛事删除规则
```
允许删除的状态：草稿(DRAFT)
禁止删除的条件：
  - 状态为报名中/进行中/已结束
  - 存在关联的报名记录
  - 存在关联的成绩记录
删除方式：逻辑删除（设置 is_deleted = 1）
```

#### BR-EVENT-004：赛事状态变更规则
```
草稿 → 报名中：
  - 必须至少有1个比赛项目
  - 必须设置报名截止日期

报名中 → 进行中：
  - 当前日期 >= 赛事开始日期
  - 或管理员手动触发

进行中 → 已结束：
  - 当前日期 > 赛事结束日期
  - 或管理员手动触发
  - 所有项目成绩已录入完成（可选）

任意状态 → 已结束（取消）：
  - 仅ADMIN可操作
  - 需填写取消原因
```

## 3. 报名管理规则

### 3.1 报名状态机

```
                    ┌─────────────┐
      提交报名      │   待审核    │
    ─────────────▶  │ (PENDING)   │
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
              ▼            │            ▼
       ┌─────────────┐     │     ┌─────────────┐
       │   已通过    │     │     │   已拒绝    │
       │ (APPROVED)  │     │     │ (REJECTED)  │
       └─────────────┘     │     └─────────────┘
                           │
                           ▼
                    ┌─────────────┐
                    │   已取消    │
                    │ (CANCELLED) │
                    └─────────────┘
```

### 3.2 报名业务规则

#### BR-REG-001：报名提交规则
```
前置条件：
  - 用户角色为 STUDENT
  - 赛事状态为 报名中(REGISTERING)
  - 当前日期 <= 报名截止日期

约束：
  - 同一学生不能重复报名同一项目
  - 同一学生在同一赛事中报名项目数 <= 3（可配置）
  - 学生信息必须完整（姓名、学号、院系、联系方式）

默认状态：待审核(PENDING)
```

#### BR-REG-002：报名审核规则
```
审核角色：ADMIN、TEACHER
可审核状态：待审核(PENDING)

通过操作：
  - 状态变更为 已通过(APPROVED)
  - 记录审核人、审核时间

拒绝操作：
  - 状态变更为 已拒绝(REJECTED)
  - 必须填写拒绝原因
  - 记录审核人、审核时间

批量审核：
  - 支持批量通过/拒绝
  - 每次最多处理100条
```

#### BR-REG-003：报名取消规则
```
学生取消：
  - 仅可取消 待审核(PENDING) 状态的报名
  - 已通过/已拒绝 状态不可取消

管理员取消：
  - 可取消任意状态的报名
  - 需填写取消原因
  - 通知学生（可选）
```

#### BR-REG-004：报名人数限制规则
```
项目人数上限：
  - 每个项目可设置报名人数上限
  - 达到上限后，新报名自动进入候补队列（可选）
  - 或直接禁止报名

性别限制：
  - 项目可设置性别限制（男/女/不限）
  - 报名时校验学生性别
```

## 4. 赛程编排规则

### 4.1 赛程业务规则

#### BR-SCH-001：赛程创建规则
```
前置条件：
  - 用户角色为 ADMIN
  - 关联的赛事状态为 报名中 或 进行中

必填字段：
  - 关联项目
  - 比赛日期
  - 开始时间、结束时间
  - 场地信息
  - 场次编号

约束：
  - 同一场地同一时间段不能有多场比赛
  - 比赛时间必须在赛事日期范围内
  - 场次编号在同一项目内唯一
```

#### BR-SCH-002：赛程冲突检测规则
```
冲突类型：
  1. 场地冲突：同一场地、同一时间段
  2. 选手冲突：同一选手、同一时间段参加多个项目

检测时机：
  - 创建赛程时
  - 修改赛程时

冲突处理：
  - 提示冲突信息
  - 阻止保存（或警告后允许保存）
```

#### BR-SCH-003：赛程修改规则
```
允许修改：
  - 赛事状态为 报名中 或 进行中
  - 比赛尚未开始

禁止修改：
  - 比赛已开始或已结束
  - 已录入成绩
```

## 5. 成绩管理规则

### 5.1 成绩业务规则

#### BR-RESULT-001：成绩录入规则
```
录入角色：ADMIN、TEACHER
前置条件：
  - 赛事状态为 进行中(ONGOING) 或 已结束(FINISHED)
  - 报名状态为 已通过(APPROVED)
  - 对应赛程已安排

必填字段：
  - 关联报名记录
  - 成绩值（根据项目类型：时间/距离/分数）
  - 名次（可自动计算）

约束：
  - 同一报名记录只能有一条成绩
  - 成绩值必须为有效数值
```

#### BR-RESULT-002：成绩计算规则
```
排名计算：
  - 田径类（时间）：时间越短排名越前
  - 田径类（距离）：距离越远排名越前
  - 球类（分数）：分数越高排名越前

积分计算（可选）：
  - 第1名：9分
  - 第2名：7分
  - 第3名：6分
  - 第4名：5分
  - 第5名：4分
  - 第6名：3分
  - 第7名：2分
  - 第8名：1分
```

#### BR-RESULT-003：成绩修改规则
```
修改角色：ADMIN、TEACHER
允许修改：
  - 赛事状态为 进行中
  - 录入后24小时内

禁止修改：
  - 赛事状态为 已结束 且超过24小时
  - 需ADMIN特殊授权才能修改
```

#### BR-RESULT-004：Excel导入规则
```
文件格式：.xls 或 .xlsx
模板字段：
  - 学号（必填，用于匹配报名记录）
  - 姓名（必填，用于校验）
  - 项目名称（必填）
  - 成绩值（必填）
  - 名次（可选，不填则自动计算）

校验规则：
  - 学号必须存在于报名记录中
  - 姓名必须与报名记录一致
  - 成绩值必须为有效数值
  - 重复数据：覆盖/跳过/报错（可配置）

导入限制：
  - 单次最多导入500条
  - 失败记录返回错误明细
```

## 6. 公告管理规则

### 6.1 公告业务规则

#### BR-NEWS-001：公告发布规则
```
发布角色：ADMIN
必填字段：
  - 公告标题
  - 公告类型
  - 公告内容

可选字段：
  - 关联赛事
  - 置顶标记
  - 发布时间（定时发布）

约束：
  - 标题长度 <= 100字符
  - 内容支持富文本
```

#### BR-NEWS-002：公告展示规则
```
排序规则：
  1. 置顶公告优先
  2. 按发布时间倒序

展示范围：
  - 所有角色可查看
  - 可按类型筛选
```

缓存策略：字典数据前端缓存，变更时刷新

## 8. 边界与约束

### 8.1 系统边界

| 边界 | 说明 |
|------|------|
| 用户来源 | 系统不提供注册功能，用户由管理员导入或对接学校统一身份认证 |
| 支付功能 | 不涉及任何支付功能 |
| 消息推送 | MVP阶段不实现消息推送，仅站内公告 |
| 移动端 | MVP阶段仅支持响应式Web，不开发原生APP |

### 8.2 数据约束

| 约束 | 说明 |
|------|------|
| 数据保留 | 历史数据永久保留，不物理删除 |
| 并发控制 | 成绩录入采用乐观锁，防止并发覆盖 |
| 数据备份 | 每日自动备份（运维层面） |

### 8.3 业务约束

| 约束 | 说明 |
|------|------|
| 报名时间 | 报名截止后不可再报名 |
| 成绩修改 | 赛事结束后成绩原则上不可修改 |
| 赛事取消 | 已开始的赛事不建议取消，需特殊审批 |

## 9. 异常处理规则

### 9.1 业务异常码

| 错误码 | 说明 | 处理建议 |
|--------|------|----------|
| `BIZ_001` | 赛事不存在 | 检查赛事ID |
| `BIZ_002` | 赛事状态不允许此操作 | 检查赛事当前状态 |
| `BIZ_003` | 报名已截止 | 提示用户报名时间已过 |
| `BIZ_004` | 重复报名 | 提示用户已报名该项目 |
| `BIZ_005` | 报名人数已满 | 提示用户该项目报名已满 |
| `BIZ_006` | 成绩已存在 | 提示是否覆盖 |
| `BIZ_007` | 赛程时间冲突 | 提示冲突详情 |
| `BIZ_008` | 权限不足 | 提示无权限操作 |

### 9.2 系统异常处理

| 异常类型 | 处理方式 |
|----------|----------|
| 数据库异常 | 记录日志，返回友好提示 |
| 网络超时 | 前端重试机制，最多3次 |
| 文件上传失败 | 提示重新上传 |
| Token过期 | 跳转登录页 |
