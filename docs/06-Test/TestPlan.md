## 4. 接口测试用例

### 4.1 认证接口

```bash
# 登录接口
POST /api/auth/login
Content-Type: application/json
{
  "username": "admin",
  "password": "123456"
}
# 预期: 200, 返回token

# 获取用户信息
GET /api/auth/info
Authorization: Bearer {token}
# 预期: 200, 返回用户信息
```

### 4.2 赛事接口

```bash
# 获取赛事列表
GET /api/events?current=1&size=10
Authorization: Bearer {token}
# 预期: 200, 返回分页数据

# 创建赛事
POST /api/events
Authorization: Bearer {admin_token}
Content-Type: application/json
{
  "name": "测试赛事",
  "type": "TRACK_FIELD",
  "startDate": "2024-04-01",
  "endDate": "2024-04-03",
  "regStartDate": "2024-03-01",
  "regEndDate": "2024-03-25"
}
# 预期: 200, 创建成功
```

### 4.3 报名接口

```bash
# 提交报名
POST /api/registrations
Authorization: Bearer {student_token}
Content-Type: application/json
{
  "eventId": 1,
  "sportItemId": 1
}
# 预期: 200, 报名成功

# 审核通过
POST /api/registrations/1/approve
Authorization: Bearer {admin_token}
# 预期: 200, 审核成功
```

## 6. 缺陷管理

### 6.1 缺陷等级

| 等级 | 说明 | 处理时限 |
|------|------|----------|
| 致命 | 系统崩溃、数据丢失 | 立即修复 |
| 严重 | 核心功能不可用 | 24小时内 |
| 一般 | 功能异常但有替代方案 | 3天内 |
| 轻微 | UI问题、体验问题 | 下个版本 |

### 6.2 缺陷报告模板

