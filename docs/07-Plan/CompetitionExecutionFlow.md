# 竞赛编排与现场检录阶段说明

## 本阶段目标

在既有赛事、项目、报名、接力队伍和赛程模块上，补齐“审核通过的参赛者进入具体场次—自动编排—生成检录编号—现场检录—学生查询个人检录信息”的流程。

本阶段使用既有增量迁移 V1 创建的 `schedule_entry` 和 `checkin_record`，不新增或删除数据库表，不要求重建业务数据库。

## 已新增接口

| 方法 | 路径 | 权限 | 用途 |
|---|---|---|---|
| GET | `/api/schedules/{scheduleId}/entries` | 管理员、教师 | 查询指定场次的编排与检录名单 |
| POST | `/api/schedules/{scheduleId}/entries/auto-assign?laneCount=8` | 管理员、教师 | 按审核通过的报名记录自动编排 |
| PUT | `/api/schedule-entries/{id}/assignment` | 管理员、教师 | 调整组别、跑道和出场顺序 |
| POST | `/api/schedule-entries/{id}/check-in` | 管理员、教师 | 更新现场检录状态 |
| DELETE | `/api/schedule-entries/{id}` | 管理员 | 移除尚未开始且尚未检录的编排记录 |
| GET | `/api/schedule-entries/my` | 学生 | 查询本人赛程、分组、跑道和检录编号 |

## 编排规则

- 只允许对“未开始”的场次执行自动编排；自动编排在事务内锁定场次记录，避免同一场次被并发重复编排。
- 个人项目只纳入已审核通过的个人报名；接力项目只纳入已审核通过的接力队伍。
- 径赛按设置的跑道数分组，跑道数限定为 1—12；组别依次为 A组、B组等。
- 田赛及非径赛项目按出场顺序排列，不分配跑道。
- 每条编排记录生成稳定的检录编号，格式为 `CK` 加八位数字编号。
- 已有编排记录的场次不会被自动覆盖；需要重新编排时，管理员先移除未开始且仍处于待检录状态的旧记录。
- 手动调整时检查同一组别的出场顺序和径赛跑道冲突。

## 检录状态

| 状态码 | 显示名称 |
|---|---|
| `PENDING` | 待检录 |
| `CHECKED_IN` | 已检录 |
| `ABSENT` | 缺席 |
| `WITHDRAWN` | 弃权 |
| `DQ` | 取消资格 |

比赛已结束或已取消后，接口不允许继续修改检录状态。检录操作记录检录人员、时间和备注。

## 前端入口

- 管理端新增“竞赛编排与检录”页面，支持选择赛程、自动编排、查看检录名单、调整编排、现场检录和移除未开始场次的待检录记录。
- 学生端新增“我的检录编号”页面，展示个人赛程、比赛时间、地点、分组、跑道和检录状态。
- “赛程安排”页面对学生隐藏新增、编辑、开始、完成和删除等管理操作。

## 本阶段验收边界

当前提交新增后端接口、前端页面和纯单元测试。正式验收仍需在隔离 MySQL 实例执行既有 V1/V2 增量迁移，并使用真实学生、教师和管理员账号验证报名数据、接力队员、并发编排、现场检录及学生查询。当前实现尚未覆盖预赛晋级、田赛试跳/试投录入、成绩发布审计和团体积分计算，这些应作为后续阶段单独实现和测试。
