## 第一阶段已实现

### 基线和安全配置

- 数据库连接信息和 JWT 签名密钥改为环境变量配置。
- 修复成绩服务接口契约，确保 Controller 调用的方法在 Service 接口中声明。
- 新增构建工作流，推送开发分支或发起 PR 时执行后端和前端检查。
- 原有初始化 SQL 仍包含 `DROP TABLE`，禁止在已有业务数据库上直接重跑。

### 个人报名和资格审核

- 报名人身份从登录态获取，报名接口限制为学生角色；服务层再次核验账号状态和学生角色。
- 核验赛事报名状态、报名日期、项目状态、性别限制和项目所属赛事。
- 个人项目限报通过赛事字段 `max_items_per_user` 配置，0 表示不限；前端赛事表单提供配置入口。
- 项目容量使用有效报名记录（待审核、已通过）计数；事务中锁定项目记录，学生限报检查同时锁定学生记录，降低并发超限风险。
- 取消或拒绝的报名记录可复用，避免与既有 `(user_id, sport_item_id, is_deleted)` 唯一约束冲突。
- 项目当前报名数根据有效报名状态重新计算，避免简单增减造成计数漂移。

### 学院、班级和审核信息

- 使用现有用户数据中的 `department` 作为学院字段、`class_name` 作为班级字段，不重复创建学生主数据。
- 报名列表增加学院、班级筛选，并展示报名人、学号、学院、班级、联系方式和审核信息。
- 修复报名状态整数编码与前端 `PENDING / APPROVED / REJECTED / CANCELLED` 的映射，以及拒绝原因 JSON 请求格式。
- “我的报名”接口支持分页和状态筛选。

### 接力队伍管理

- 新增接力队伍和队员实体、Mapper、Service、Controller。
- 学生可以创建接力队伍、查询本人队伍、调整待审核队伍的队员并取消待审核队伍；教师/管理员可以分页查询和审核。
- 接力项目可配置正式队员数和替补人数；队长自动计入正式队员。
- 队员必须为状态正常的学生，并与队伍属于同一学院；同一名学生不能同时加入同一赛事、同一项目下的多支待审/已通过队伍。
- 接力项目人数上限按队伍数量解释；项目当前报名数同步为有效接力队伍数量。
- 新增“接力组队”页面，并从赛事详情页提供接力项目入口。

### 测试

新增单元测试覆盖报名状态映射、非法状态拒绝、接力队长自动加入、接力队员重复和超出队伍人数限制等规则。
